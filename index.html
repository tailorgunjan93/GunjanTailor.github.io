"The document normalization engine RAG has always needed."

v0.8.6–0.8.7Bug Fix
Blank Window on Launch
Vite absolute paths, wrong loadFile() target, HashRouter mismatch, and CORS null-origin — four independent root causes producing one blank screen. Traced through Electron renderer logs to isolate each.
Root cause: Vite/Electron path mismatch
v0.8.9Bug Fix
tiktoken "Unknown encoding cl100k_base"
tiktoken_ext is a namespace package — PyInstaller skips it silently. Fixed with collect_submodules() in the spec file and a runtime hook that pre-imports the encoding plugins before app code runs.
Root cause: PyInstaller namespace package exclusion
v0.9.1–0.9.4Bug Fix
Wrong API Key + Stale Model Catalogues
effective_key always used the stored key regardless of which provider was selected. Groq and Cerebras model IDs were also outdated — retired slugs and a wrong format (llama-3.3-70b vs the actual llama3.3-70b).
Root cause: static catalogues + provider key routing
v0.9.5Bug Fix
"filePaths is not iterable"
The IPC handler returned a plain string array, but the renderer accessed result.filePaths. TypeScript declared the right shape in electron.d.ts — but main.js is JavaScript. No compiler error. Fixed by returning {canceled, filePaths} from the handler.
Root cause: JS/TS type boundary not enforced at runtime
v0.9.7–0.9.8Tests
Full E2E Coverage — 361 Tests
KB, Chat, Reader, and Settings — every zero-coverage workflow got full browser E2E with a mocked API, plus Electron E2E against a real SQLite backend. Playwright drives the packaged binary, not localhost.
216 Python · 90+ browser E2E · 55 Electron E2E
v0.9.9Bug Fix
Truncated JSON — Quiz & Flashcard Generation
max_tokens=2048 was too low — the LLM hit the limit mid-string, producing invalid JSON. Built _repair_truncated_json(): a bracket-stack function that closes any open string, array, or object in reverse order so partial output still parses. 8 unit tests cover it.
Root cause: token budget too low for structured LLM output
v0.10.0Bug Fix
NSIS Auto-Update Fails with Error 2
oneClick: true installs silently to %LOCALAPPDATA%\Programs. If the user had picked a different path on first install, the registry uninstall key pointed nowhere — ERROR_FILE_NOT_FOUND on every subsequent update. Fixed: oneClick: false + allowToChangeInstallationDirectory: true.
Root cause: NSIS registry path divergence on custom installs
